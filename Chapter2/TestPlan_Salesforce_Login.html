Executive Summary: This plan defines the approach to validate the Salesforce login experience for locale=in, covering functional correctness (valid/invalid authentication), UI behavior (username, password, Login, Remember Me), error handling, and locale/navigation sanity. It combines risk-based manual testing with Selenium/TestNG automation to provide fast regression feedback while managing constraints such as credential availability, MFA/CAPTCHA, and potential UI changes.

1. Objective

Validate the functionality, usability, reliability, and UI-level security behavior of the Salesforce login page for locale=in. Testing will confirm that:

  • Authorized users can authenticate with valid credentials and reach the intended Salesforce experience.
  • Invalid or unauthorized attempts are handled with clear, consistent error messaging and no sensitive data leakage.
  • Core controls (username, password, Login, Remember Me, relevant links) behave as expected across supported environments.
  • Defects are identified early, prioritized by risk, and reported with sufficient evidence for resolution.

3. Test Strategy

Approach

  • Black-box, risk-based testing focused on authentication-critical paths.
  • Layered execution: smoke, functional, regression, and time-boxed exploratory testing.
  • Automation for stable, high-value scenarios; manual coverage for usability/visual/accessibility nuances.

Design Techniques

  • Equivalence Partitioning (valid/invalid/empty inputs).
  • Boundary Value Analysis (safe input limits).
  • Decision Tables (username/password/Remember Me combinations).
  • Error Guessing (common user mistakes and edge behaviors).

3.3 Entry & Exit Criteria

Entry Criteria

  • AUT URL accessible and stable for testing.
  • Test data available (invalid sets; valid credentials provided securely if executing valid-login path).
  • Browsers/WebDriver and framework build are ready.
  • Plan/cases reviewed for formal cycles.

Exit Criteria

  • Planned cases executed or formally deferred with approval.
  • No unresolved Critical/Blocker defects without approved workaround/risk acceptance.
  • Test summary/report delivered with pass/fail, defect status, and open risks.
